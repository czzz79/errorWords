中文发音混淆文本扰动生成说明（第一版）
========================================

一、目的
--------

本方案用于根据常见中文发音混淆规则，对术语或句子中的目标词进行文本阶段扰动，
再将扰动文本依次送入 TTS 和 ASR，获得新的 ASR 混淆词。

整体流程：

标准文本
→ 标准文本转带声调拼音
→ 对目标音节应用一条发音混淆规则
→ 将扰动后的拼音转换为由高频词/高频字组成的文本
→ TTS 合成音频
→ ASR 识别
→ 提取目标位置的混淆文本

注意：

1. 扰动文本只是 TTS 的“发音载体”，训练或评测时的原始 GT 仍然是标准文本。
2. 第一版暂不统计真实频次，不计算每条规则的发生概率。
3. 第一版建议枚举“一次只修改一个音节”的全部候选，而不是按概率随机采样。
4. 公共规则只用于提供候选，业务 GT 用于确认哪些方向和哪些特殊混淆在当前场景中有效。


二、混淆规则从哪里获取
----------------------

可以先直接参考现成输入法中的“模糊拼音/Fuzzy Pinyin”规则，不需要从零设计。

1. Microsoft Pinyin / Microsoft SwiftKey Fuzzy Pinyin

   用途：
   提供常见的模糊拼音映射概念，可作为规则来源之一。

   参考：
   https://support.microsoft.com/en-us/windows/hardware/input-devices/microsoft-simplified-chinese-ime
   https://support.microsoft.com/en-us/swiftkey-keyboard/how-is-chinese-set-up-with-microsoft-swiftkey-keyboard-for-android

2. ibus-libpinyin

   用途：
   其公开说明中列出了较完整的模糊拼音和拼音纠正规则，例如：
   z/zh、c/ch、s/sh、l/n、f/h、l/r、g/k、an/ang、en/eng、in/ing 等。

   参考：
   https://github.com/libpinyin/ibus-libpinyin/wiki/ibus-libpinyin-features

3. Rime / 雾凇拼音配置

   用途：
   可以查看输入方案中的拼音派生、纠错和模糊拼音配置，并根据需要补充扩展规则。

   参考：
   https://github.com/iDvel/rime-ice

这些规则原本多以“双向可混淆关系”描述，例如：

z ↔ zh
in ↔ ing

在实现中应拆成两条有方向的规则：

z  → zh
zh → z
in  → ing
ing → in

虽然第一版暂不统计频次，也应保存方向，方便后续根据真实 GT 统计两个方向各自的发生率。


三、第一版建议使用的规则
------------------------

3.1 一级规则：优先启用
~~~~~~~~~~~~~~~~~~~~~~

这部分是较常见、泛化风险较低的发音混淆。

声母：

z  → zh
zh → z
c  → ch
ch → c
s  → sh
sh → s

韵母：

an  → ang
ang → an
en  → eng
eng → en
in  → ing
ing → in

示例：

宗友 → 钟友        zong → zhong
组网图 → 主网图    zu → zhu
数通 → 苏通        shu → su
演进 → 眼镜        jin → jing
老王 → 老万        wang → wan


3.2 二级规则：默认启用，但限制每次只使用一条
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

声母：

n → l
l → n
l → r
r → l
f → h
h → f

韵母：

ian  → iang
iang → ian
uan  → uang
uang → uan
un   → ong
ong  → un

鼻韵尾删除：

ing  → i
iang → ia
ang  → a
eng  → e

示例：

广荣 → 广龙        rong → long
合入 → 河路        ru → lu
鹭兴 → 露西        xing → xi
投屏 → 头皮        ping → pi
项目 → 夏目        xiang → xia


3.3 三级规则：可选启用
~~~~~~~~~~~~~~~~~~~~~~

这些规则更依赖具体说话人、音色和声学环境，第一版可作为扩展候选：

b ↔ p
d ↔ t
g ↔ k
j ↔ q
j ↔ x
q ↔ x

示例：

白板 → 排版        bai → pai
周清 → 周星        qing → xing
魏翔 → 魏强        xiang → qiang

建议给三级规则设置开关，便于单独评估其生成质量。


3.4 暂不泛化的规则
~~~~~~~~~~~~~~~~~~

以下情况不要直接提取为通用发音规则：

摘要 → 弹药
韩总 → 张总
云会议 → 零会议
贺行 → 贺总

原因是它们可能同时包含：

1. ASR 语言模型偏置；
2. 人名或业务术语不在词表；
3. 多个音节同时变化；
4. 句子上下文重新解码；
5. 声学噪声或切分错误。

这类数据有两种用法：

1. 作为“术语级直接混淆候选”保存，只对该术语使用；
2. 作为最终 ASR 生成效果的评测样本，不泛化到其他词。


四、规则文件如何保存
--------------------

即使暂不统计频次，也建议一行只保存一个方向。

推荐 CSV/TXT 格式：

# type,source,target,level,origin
initial,z,zh,1,public
initial,zh,z,1,public
initial,c,ch,1,public
initial,ch,c,1,public
initial,s,sh,1,public
initial,sh,s,1,public
final,an,ang,1,public
final,ang,an,1,public
final,en,eng,1,public
final,eng,en,1,public
final,in,ing,1,public
final,ing,in,1,public
initial,n,l,2,public
initial,l,n,2,public
initial,l,r,2,public
initial,r,l,2,public
final,ing,i,2,public
final,iang,ia,2,public

字段说明：

type：
    initial 表示声母替换；
    final 表示韵母替换；
    syllable_delete 表示完整音节删除；
    term_specific 表示术语专用混淆。

source、target：
    保存有方向的原音和目标音。

level：
    1 表示优先规则；
    2 表示普通扩展规则；
    3 表示低优先级规则。

origin：
    public 表示来自公共模糊拼音规则；
    gt 表示从业务 GT 中观察到；
    manual 表示人工添加。

暂时不需要 probability 或 count 字段，后续有完整统计数据时再增加。


五、文本阶段怎么使用
--------------------

5.1 确定目标词
~~~~~~~~~~~~~~

输入完整句子以及需要扰动的目标术语，例如：

完整句子：
这个版本目前没有演进能力。

目标术语：
没有演进

仅扰动目标术语，不修改句子其他区域。


5.2 将目标术语转为带声调拼音
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

例如：

没有演进
mei3 you3 yan3 jin4

需要保留声调。声母或韵母变化后，第一版默认沿用原音节声调。

多音字必须使用术语读音词典覆盖默认读音，例如：

农行总部 → nong2 hang2 zong3 bu4

不能完全依赖单字默认拼音。


5.3 枚举单次扰动
~~~~~~~~~~~~~~~~

检查每个音节能够匹配哪些规则，每个候选只应用一条规则。

例如：

jin4 = j + in + 4

匹配：

in → ing

得到：

jing4 = j + ing + 4

因此：

mei3 you3 yan3 jin4
→
mei3 you3 yan3 jing4

第一版不建议在同一个短术语中连续修改两个或更多音节，否则生成文本容易偏离真实发音错误。


5.4 将扰动拼音转换成高频文本
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

转换优先级：

高频词
> 高频双字或多字组合
> 高频单字组合

例如：

扰动拼音：
mei3 you3 yan3 jing4

优先生成：
没有眼镜

不优先生成：
每有演静
美友严境

文本候选应满足：

1. 转回拼音后必须与目标扰动拼音完全一致；
2. 声调必须一致；
3. 优先使用常用词和常用字；
4. 尽量避免多音字；
5. 避免生僻字；
6. 同一拼音候选只保留 Top-K，例如 Top-3；
7. 如果没有合适的高频词，再使用高频单字拼接。

注意：

不要只按照每个音节独立选择频率最高的字。
应优先匹配跨音节的高频词，例如：

yan3 jing4 → 眼镜

而不是分别选择两个互不相关的高频单字。


5.5 将载体文本放回原句
~~~~~~~~~~~~~~~~~~~~~~

原句：

这个版本目前没有演进能力。

扰动载体句：

这个版本目前没有眼镜能力。

这里“没有眼镜”只是用来让 TTS 发出目标扰动读音。
数据中的原始 GT 仍然保存为：

这个版本目前没有演进能力。


5.6 TTS 和 ASR
~~~~~~~~~~~~~~

将扰动载体句送入 TTS：

这个版本目前没有眼镜能力。
→ TTS 音频
→ ASR

ASR 可能输出：

这个版本目前没有眼镜能力。
这个版本目前没有演进能力。
这个版本目前没有眼睛能力。
其他近音结果。

这些结果都可以记录，后续根据筛选规则判断是否保留。


六、生成候选的推荐策略
----------------------

因为第一版暂不统计频次，建议不使用概率随机采样，而采用“规则枚举 + 数量限制”。

推荐配置：

1. 每个术语一次最多修改一个音节；
2. 每个音节分别枚举所有可用规则；
3. 同一个扰动拼音只保留一次；
4. 每个扰动拼音最多生成 3 个高频文本；
5. 每个原始术语最多保留 10 个扰动文本；
6. 优先保留一级规则，其次保留二级规则；
7. 三级规则通过配置开关决定是否生成；
8. 完整音节插入和删除第一版默认关闭；
9. 业务 GT 中已经出现过的方向优先保留；
10. 公共规则中未在 GT 出现的方向可以保留，用于探索新混淆。


七、业务 GT 如何参与
--------------------

当前 GT 格式：

标准术语 | 已识别混淆词

例如：

演进 | 眼镜
组网图 | 主网图
鹭兴 | 露西

第一版可以做两件事。


7.1 确认公共规则方向
~~~~~~~~~~~~~~~~~~~~

演进 → 眼镜：

jin → jing
得到：
in → ing

组网图 → 主网图：

zu → zhu
得到：
z → zh

鹭兴 → 露西：

xing → xi
得到：
ing → i

将这些方向标记为：

origin = gt

但暂不计算出现次数和概率。


7.2 保存术语专用混淆
~~~~~~~~~~~~~~~~~~~~

对于无法解释为单个通用规则的 GT：

摘要 → 弹药

保存为：

term_specific,摘要,弹药,3,gt

该规则只能在原词为“摘要”时使用，不能把所有 zhai 音节都改为 dan。


八、完整示例
------------

示例一：韵母替换

标准句：
这个版本目前没有演进能力。

目标术语：
演进

标准拼音：
yan3 jin4

应用规则：
in → ing

扰动拼音：
yan3 jing4

高频文本：
眼镜

TTS 输入：
这个版本目前没有眼镜能力。

保留标签：

original_text = 这个版本目前没有演进能力。
original_term = 演进
rule_type = final
rule_source = in
rule_target = ing
perturbed_pinyin = yan3 jing4
carrier_term = 眼镜
tts_text = 这个版本目前没有眼镜能力。


示例二：声母替换

标准句：
请把组网图发出来。

目标术语：
组网图

标准拼音：
zu3 wang3 tu2

应用规则：
z → zh

扰动拼音：
zhu3 wang3 tu2

高频文本：
主网图

TTS 输入：
请把主网图发出来。


示例三：鼻韵尾删除

标准句：
请联系鹭兴确认一下。

目标术语：
鹭兴

标准拼音：
lu4 xing1

应用规则：
ing → i

扰动拼音：
lu4 xi1

高频文本：
露西

TTS 输入：
请联系露西确认一下。

----------------------

每条生成数据建议保存：

{
    "original_text": "这个版本目前没有演进能力。",
    "original_term": "演进",
    "original_pinyin": ["yan3", "jin4"],
    "rule_type": "final",
    "rule_source": "in",
    "rule_target": "ing",
    "rule_level": 1,
    "rule_origin": "gt",
    "perturbed_pinyin": ["yan3", "jing4"],
    "carrier_term": "眼镜",
    "tts_text": "这个版本目前没有眼镜能力。",
    "tts_audio": "",
    "asr_text": ""
}

后续增加频次统计时，再补充：

rule_count
source_total_count
rule_probability


十、第一版实现步骤
------------------

1. 从 libpinyin、Microsoft Fuzzy Pinyin 和 Rime 配置整理公共规则；
2. 将双向关系拆成两条有方向的规则；
3. 用业务 GT 对齐标准词和混淆词的拼音；
4. 标记 GT 中已经出现过的规则方向；
5. 将无法归纳的 GT 保存为术语专用混淆；
6. 标准术语转换为带声调拼音；
7. 每次应用一条声母或韵母规则；
8. 将扰动拼音解码成高频词或高频字文本；
9. 校验载体文本的拼音与扰动拼音完全一致；
10. 将载体文本放回句子并执行 TTS；
11. 将音频送入 ASR；
12. 保存 ASR 结果及完整生成链路；
13. 第一版先评估规则覆盖率和生成质量，暂不统计真实频次。


十一、第一版结论
----------------

第一版无需学习一套新的发音规则，也无需计算规则概率。

公共模糊拼音规则负责回答：

“哪些发音可能互相混淆？”

业务 GT 负责回答：

“当前业务中观察到了哪些具体方向和术语级错误？”

文本生成模块负责：

“把扰动后的拼音转换成能够被 TTS 稳定朗读的高频文本。”

第一版采用：

公共双向规则
→ 拆分为有方向规则
→ 每次单音节、单规则枚举
→ 高频词优先生成载体文本
→ TTS
→ ASR
→ 收集新的混淆词

后续获得未去重的真实 ASR 错误数据和原始文本总量后，再统计每条规则的方向频次和真实发生概率。
